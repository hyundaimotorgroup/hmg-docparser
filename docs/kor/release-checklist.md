# 릴리스 점검표

> 원문: [release-checklist.md](../release-checklist.md).

특정 릴리스 후보를 기준으로 항목별 커밋·버전·검토자·날짜·명령/환경·결과·증거 위치를
기록합니다. 정책 작성이나 과거 개발 실행만으로 릴리스 검증이 완료되지는 않습니다.
아래 미완료 항목은 공개 작업이며 사용자 문서 미작성 표시가 아닙니다.

## 권리와 자산

- [ ] 이번 릴리스의 Apache-2.0, 권리자·연도, 파서 라이선스 적용 범위를 확인합니다.
- [ ] 검토된 [LICENSE](../../LICENSE)와 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES)를
  공개 소스에 포함하고 제공된 라이선스 전문·의존성 이름/버전·출처·저작권을 보존합니다.
- [ ] 라우터 가중치 배포물에 Apache-2.0 LICENSE·NOTICE를 포함하고 저작권 고지를 보존합니다.
- [ ] [자산 목록](../assets/manifest.json)의 체크포인트·PDF·이미지·정답·pickle에 대해
  출처·권리자·라이선스·재배포 허가·버전·SHA-256을 기록하거나 릴리스에서 제외합니다.
- [ ] 제3자 라이선스·고지를 보존하고 실제 parser/Dolphin/Paddle 배포물과 PDFium의
  의존 라이선스를 확인합니다.
- [ ] 모델 사용·배포 조건을 확인합니다. 상업적 활용에는 PP-DocLayoutV3를 권장합니다.
  Dolphin v2는 연구 라이선스 준수 또는 별도 상업 허가 근거가 필요합니다. 소개하는
  어댑터도 실제 확인합니다.

## 보안과 의존성

- [ ] 후보 파일과 Git 이력의 비밀값·내부 주소·기밀 내용·불필요한 산출물을 검사합니다.
  `.gitignore`만으로 추적 파일과 과거 이력의 정리가 증명되지는 않습니다.
- [ ] 세 환경의 직접/전이 의존성, 발견 사항과 prerelease pin을 검토하고 버전을 기록한
  뒤 `python -m pip check`를 실행합니다.
- [ ] 관련 입력 한도 테스트, 루프백 실행, 요청 한도, 안전한 YAML 처리, 예제 정제를
  확인합니다.
- [ ] 대상 저장소의 secret-scan 실행과 필수 검사를 확인합니다. 로컬 workflow 설정만으로
  실행 성공이 증명되지는 않습니다.

## 후보 설치와 구성

- [ ] 후보를 새로 clone해 문서의 OS/Python 환경에서 설치하고 명령·의존성을 기록합니다.
- [ ] CLI 도움말, 오프라인 컴파일 예제, 공개 YAML, 환경변수 참조, DTO 연결과 출력
  노드를 확인합니다.
- [ ] 문서가 참조하는 테스트·보조 모듈·튜토리얼·UI 파일을 후보에 포함합니다.
  배포물에 없는 테스트를 안내하지 않습니다.
- [ ] 비공개 fixture 기본값은 재배포 가능한 샘플이나 사용자 입력 경로로 바꾸고 예제
  파일의 존재를 확인합니다.

## 실행 검증

- [ ] 허가된 문서·제공자로 로컬 퀵스타트를 실행하고 최종 Markdown, `[Error]`, 표·이미지,
  보관 산출물을 검사합니다.
- [ ] 라우터 가중치와 소개하는 각 프로필을 확인하고 해시·모델 버전·자원·추론 결과를 기록합니다.
- [ ] vLLM/Triton 추론 계약과 managed/group 전체 실행을 확인한 뒤 검증된 조합으로 설명합니다.
- [ ] 같은 그래프·입력 식별값의 회귀 기준을 기록하고 프로필별 출력 루트와 비교 결과를 보존합니다.
- [ ] Langfuse 전달을 소개한다면 허가된 실제 전달을 확인합니다.
- [ ] Confluence의 로더/컴파일·신규 생성·갱신·첨부 교체·전체 CLI를 구분해 허가된 공간에서
  소개 범위만큼 확인합니다.

- [ ] 후보의 Global Context 생략 회귀를 실행하고 L1 렌더링·요청 0회,
  L2·레벨 미상의 호출, 내용·오류·취소·편집기 왕복 보존을 확인합니다. 실제 품질·비용
  비교에 `skip_levels`를 기록합니다. 과거 벤치마크는 새 정책의 품질·절감액 근거가 아닙니다.

## 문서와 공개

- [ ] 영문·한국어, 상대 링크, 예제, 정책, 모델 조건, 제3자 고지를 확인하고 작성 대기 문구를 제거합니다.
- [ ] 평가 데이터 공개 권리와 README 점수의 근거를 확인하고 judge·모델·설정 버전을 기록합니다.
- [ ] 공개 예제·벤치마크 산출물의 원문·개인정보·제공자 정보를 검토합니다.
- [ ] 조직 CLA의 PR 동의/검증 절차, PSIRT·행동 강령 연락처, 일반 문의 경로를 확인합니다.
- [ ] 릴리스 버전·날짜를 정해 `[Unreleased]`를 갱신하고 소스/자산 해시와 검증 한계를 포함한
  tag·릴리스 노트를 준비합니다.
- [ ] 선행IP팀의 가이드와 컨펌에 따라 최종 공개 검토·승인을 확인해 선택한 후보만 게시하고
  사전 안내를 현재 릴리스 정보로 바꿉니다.
